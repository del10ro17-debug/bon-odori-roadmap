まるつけアプリ Cursor 引き継ぎメモ

作成日: 2026-06-25 JST。Codex上で試作していた「宿題の丸つけ、未回答なら解答作成」アプリの現状整理。

やりたいこと

  1. 問題を写真で撮る。
  2. 写真内に子どもの答えが書いてあれば、答え合わせをする。
  3. 答えが書いてなければ、AIが問題を解いて答えを教える。

重要: 未回答は単なる「要確認」で終わらせず、correct_answer に保護者がそのまま使える解答例を出す。

現在入っている実装

フロントエンド

  • static/index.html の答案入力は multiple 対応済み。
  • capture は外してあり、カメラロールから選択できる。
  • 複数写真はJPEG変換後、FormData に images として送る。
  • 未記入かつAIが解いたものは、画面上で 解答例 と表示する修正を入れた。

バックエンド

  • app.py は images: Optional[list[UploadFile]] を受け取る。
  • 答案写真は最大 MAX_ANSWER_IMAGES = 6。
  • 旧単一フィールド image も互換で残している。
  • OPENAI_API_KEY が無い場合、デモ結果ではなくエラーを返す。

AI呼び出し

  • grader.py はOpenAI SDK import待ちが遅かったため、SDKを使わず urllib.request で /v1/chat/completions を直接呼ぶ形に変更済み。
  • response_format: json_schema を指定して構造化JSONを返させている。
  • 出力上限は大きめに変更済み。未指定時は max_output_tokens = 8000。
  • 画像読み取りは全学年で image_detail = high。

直近で起きていた問題と対応

サンプルしか出ない 当初、動いているアプリが ANTHROPIC_API_KEY を見ており、キー未設定でデモ結果に落ちていた。現在は OPENAI_API_KEY に切り替え、デモ分岐は廃止。
ずっと返ってこない OpenAI SDKの初回importがローカルで重かった。SDKを外しREST API直叩きに変更後、API応答は数秒から十数秒で返るようになった。
JSONとして読めない 問題数が多い写真に対して出力上限が小さく、返答が途中で切れていた。出力上限を増やし、finish_reason == "length" の場合は分かるエラーを返すようにした。
未回答なのに答えが出ない プロンプトを修正し、答えが未記入なら child_answer="（未記入）", basis="solved", correct_answer に解答例を書く方針にした。

実テスト結果

ユーザー添付の実画像でローカルAPIを直接テストした。

写真1 算数、大きな数の読み書き。HTTP 200 約14秒。未記入問題に correct_answer が返った。全29 items。
写真2 国語、擬声語/擬態語。HTTP 200 約7秒。未記入問題に解答例が返った。全11 items。

ただし、見開き全体を1枚で撮ると読み取りミスが残る。Cursor側では、写真の前処理、範囲指定、ページ分割、設問抽出を強化するのが次の本筋。

現状の課題

  1. 読み取り精度: 見開き写真では問題文や選択肢の読み間違いがある。片ページ、または大問単位で撮ると安定する。
  2. UIのフィードバック: APIエラー時にユーザーへ何が起きたかをもっと分かりやすく表示すべき。
  3. 設問数が多い時のUX: 全問一括ではなく、「写真を分割して処理」「大問ごとに処理」「最初のN問だけ処理」などの設計が必要。
  4. 採点と解答作成の分離: 今は同じJSONで処理しているが、内部的には mode = grade と mode = solve を分けた方が安定する。
  5. 解答欄の有無判定: 子どもの手書き回答があるかどうかの判定がまだ曖昧。画像上の空欄判定を強化したい。

次にCursorでやるとよいこと

  1. grader.py のプロンプトを整理し、仕様を「採点」「解答作成」に明確に分ける。
  2. フロントにモード表示を追加する。例: 「答え合わせ中」「解答例を作成中」。
  3. 写真アップロード後に、画像をアプリ内でトリミングまたは回転できるようにする。
  4. APIレスポンスに mode または result_type を追加する。例: graded, answer_example, unreadable。
  5. 選択肢問題では選択肢を抽出してから回答させる二段階処理にする。
  6. 大きい見開き写真は、アプリ側で「片ページずつ撮ると精度が上がります」と出す。

注意

  • .env のAPIキーはCursorに渡してもよいが、スクショや共有資料には載せない。
  • OpenAIモデル名は現在 OPENAI_FAST_MODEL=gpt-5.4-mini, OPENAI_PRECISE_MODEL=gpt-5.5 が設定されている。もしAPIエラーが出る場合は、利用可能なモデル名に差し替える。
  • 現在のゴールは完成品ではなく、まず「未回答なら答えを出す」が確実に動く状態にすること。
